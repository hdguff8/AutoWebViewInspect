# WebDebuggerGo 技术实现文档

## 1. 项目概述
WebDebuggerGo 是一款基于 PySide6 开发的自动化 Android WebView 离线调试终端。它集成了 ADB 调试、端口转发、WebSocket 代理以及 Chrome DevTools 前端，旨在为开发者提供一个无需依赖外部 Chrome 浏览器、即开即用的移动端 Web 调试环境。

## 2. 技术栈
- **GUI 框架**: [PySide6](https://doc.qt.io/qtforpython-6/) (Qt for Python)
- **调试引擎**: [Chrome DevTools Frontend](https://github.com/ChromeDevTools/devtools-frontend) (本地集成版)
- **底层通信**: [ADB (Android Debug Bridge)](https://developer.android.com/studio/command-line/adb)
- **网络通信**: WebSocket, HTTP/TCP Proxy
- **打包工具**: PyInstaller

## 3. 核心架构设计

项目采用模块化设计，主要分为三层：
1.  **UI 层 (`pages/`)**: 负责各功能页面的视图展现与交互。
2.  **核心层 (`core/`)**: 包含 ADB 桥接、WebSocket 代理、异步扫描等关键逻辑。
3.  **应用管理层 (`main_app.py`)**: 负责初始化、全局状态管理及模块间协调。

### 3.1 核心数据流
1.  `ScanWorker` 定期轮询 ADB 设备。
2.  `ADBDebuggerBridge` 探测设备上的 WebView Sockets 并建立 `adb forward` 转发。
3.  `WSProxyThread` 启动 TCP 代理，拦截并修改 WebSocket 握手头。
4.  `DebugBrowserView` 加载本地 DevTools 页面，通过代理端口连接到 Android 设备。

## 4. 关键技术点实现

### 4.1 ADB 自动化探测与深度原理 (`core/core_bridge.py`)
系统通过读取 `/proc/net/unix` 探测 Android 系统中所有包含 `webview_devtools_remote` 关键字的 Unix 套接字。

#### **为什么是 `/proc/net/unix`？**
- **虚拟文件系统 (procfs)**: `/proc` 不是磁盘上的真实文件夹，而是 Linux 内核提供的实时状态接口。`/proc/net/unix` 记录了当前系统中所有活跃的 **Unix Domain Sockets (UDS)**。
- **Unix Domain Sockets vs TCP**: UDS 是用于同一台机器上进程间通信 (IPC) 的高效手段。Android WebView 默认不在 TCP 端口上监听（为了安全），而是创建一个抽象命名空间的 UDS。
- **探测逻辑**: 只要 App 开启了 WebView 调试（`setWebContentsDebuggingEnabled(true)`），内核就会在 `/proc/net/unix` 中暴露出名为 `webview_devtools_remote_<pid>` 的套接字。本工具通过 `adb shell grep` 扫描该文件，即可在无需 Root 权限的情况下精准定位所有可调试的页面。

### 4.2 端口协作与 403 绕过深度解析 (`core/proxy_server.py`)
系统中存在两个关键端口：**9222 (目标端口)** 与 **9223 (代理端口)**。

#### **9222 端口：ADB 隧道端**
- **作用**: 它是 Chrome DevTools Protocol (CDP) 的标准调试端口。
- **实现**: 工具执行 `adb forward tcp:9222 localabstract:webview_devtools_remote_xxx`，将 PC 端的 TCP 9222 流量映射到手机端的 Unix 套接字。
- **局限**: 直接访问此端口会因浏览器同源策略 (CORS) 导致 **403 Forbidden**，因为请求头的 `Origin` 字段与手机端期望的值不符。

#### **9223 端口：WebSocket 代理端**
- **作用**: 充当“流量清洗站”，专门解决跨域 403 问题。
- **协作流程**:
    1.  **拦截**: `DebugBrowserView` 连接 `ws://127.0.0.1:9223`。
    2.  **改写**: `WSProxyThread` 接收到请求后，通过正则匹配**强行删除 `Origin` 头部**，并将 `Host` 伪装为 `127.0.0.1:9222`。
    3.  **转发**: 代理将修改后的合法请求发给 9222 端口，手机端认为这是合法的本地请求，从而握手成功。
    4.  **透明中继**: 握手完成后，代理进入双向透明转发模式，不再干预业务数据。

### 4.3 浏览器安全配置 (`core/debug_view.py`)
为了在 `QWebEngineView` 中运行功能完整的 DevTools：
- 开启 `LocalContentCanAccessRemoteUrls` 和 `LocalContentCanAccessFileUrls`。
- 关闭跨域限制，允许 JavaScript 访问剪贴板。

### 4.4 日志重定向系统 (`core/utils.py`)
通过自定义 `LogStream` 类重定向 `sys.stdout` 和 `sys.stderr`，将控制台输出实时推送到 UI 的“日志”页面，方便排查问题。

## 5. 模块功能说明

| 模块 | 文件 | 功能描述 |
| :--- | :--- | :--- |
| **入口** | `main_app.py` | 启动入口、主界面布局、模块调度 |
| **ADB 桥接** | `core/core_bridge.py` | ADB 命令封装、Socket 探测、端口转发管理 |
| **代理服务** | `core/proxy_server.py` | TCP/WebSocket 代理，处理 403 跨域问题 |
| **扫描器** | `core/scan_worker.py` | 后台异步轮询设备与页面状态 |
| **调试视图** | `core/debug_view.py` | 封装 Chromium 浏览器组件，配置安全策略 |
| **UI 页面** | `pages/debug_page.py` | ADB 维护工具箱、故障排查引导 |
| **UI 页面** | `pages/log_page.py` | 分级日志实时展现与筛选 |
| **UI 页面** | `pages/settings_page.py` | ADB 运行模式（内置/系统）配置 |
| **工具类** | `core/utils.py` | 资源路径处理、日志流转发 |

## 6. 编译与打包 (`build_exe.py`)
项目支持通过 PyInstaller 进行一键打包。打包脚本自动处理：
- 包含 `adb` 二进制文件。
- 包含 `chrome_devtools_frontend` 静态资源。
- 配置 `--noconsole` 隐藏黑框，并设置程序图标。

## 7. 常见问题处理
- **ADB 冲突**: 用户可切换内置/系统 ADB 模式。
- **资源释放**: 提供“停止监控”功能，允许其他工具（如 Edge 浏览器）接管 ADB 转发端口。
